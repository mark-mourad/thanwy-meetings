# Thanwy Meetings — Full-Stack Web Application

Build a complete production-ready web application called **"Thanwy Meetings"** for managing and tracking Sunday School students ("مخدومين") and servants ("خدام").

The application must be **Arabic-first, RTL, mobile-first**, modern, responsive, and easy to use.

The attached screenshots are **visual references**, not exact pixel-perfect requirements. Use them to understand the desired structure, spacing, hierarchy, cards, dashboard composition, and mobile-app feeling.

The uploaded `DESIGN.md` file is the primary source for the visual design system and must be followed.

---

# 1. PRODUCT CONCEPT

The website has two main user roles:

1. **مخدوم — Student**
2. **خادم — Servant**

Both roles use the same login system, but after authentication the application must automatically load the correct dashboard based on the user's role.

The goal of the application is to allow:

### Students

* Create an account.
* Select their school year.
* Select their Sunday School class.
* View their upcoming meetings/events.
* View their spiritual activity.
* Record their prayers.
* Record Bible readings.
* View Bible study assignments.
* Submit Bible studies.
* View attendance.
* Use their personal QR code for attendance.

### Servants

* Receive an invitation/signup link from the system.
* Create a servant account.
* Select the school year and class they serve.
* View all students belonging to their class.
* Track attendance.
* Scan student QR codes.
* View individual student profiles.
* Monitor spiritual activities.
* Monitor Bible readings.
* Create Bible study assignments.
* Track assignment submissions.
* Manage/view upcoming events.

# 10. SERVANT ACCOUNT

Servants must NOT use the public student signup flow.

Instead, the system must support an **invitation link**.

A servant receives a unique invitation link.

Example conceptual flow:

```text
Admin/System
      ↓
Generate servant invitation
      ↓
Send invitation link
      ↓
Servant opens link
      ↓
Creates account
      ↓
Chooses:
- Name
- Email
- Password
- School year
- Class
      ↓
Account role = SERVANT
```

The invitation token must be secure, unique, and expire after a configurable amount of time.

Do not allow users to manipulate the URL to turn a student account into a servant account.

Role must be stored and validated server-side.
